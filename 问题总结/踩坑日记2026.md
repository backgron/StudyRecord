
# 踩坑日记2026

### 1. ElementUI 表格固定列遮挡后面内容、固定列样式偏离

**现象**
- 使用 `el-table` 配置了固定列（`fixed` / `fixed="right"`）后：固定列会遮挡后面的滚动内容，或固定列与主体表格出现错位（边框/背景/行高对不上）。

**原因**
- ElementUI 的固定列不是“真正同一张表”，而是单独渲染了一份固定区域表格，通过定位叠在主表上；当出现滚动条、行高不一致、祖先元素产生新的层叠上下文（例如 `transform`/`filter`），就更容易出现遮挡或偏移。

**解决方案**
- 避免在 `el-table` 的祖先节点上使用 `transform` / `filter` / `perspective` 等会创建新层叠上下文的属性（尤其是做居中/缩放/动画时）。
- 明确固定列背景与层级，避免透出/遮挡异常；必要时为固定列区域补背景色与 `z-index`。
- 尽量保证行高一致：统一 `line-height` / `padding`，避免某些列文本换行导致固定列与主体行高计算差异。

**示例（CSS 修复思路）**
```css
/* 固定列区域不要“透明盖住” */
.el-table__fixed,
.el-table__fixed-right {
	background: #fff;
	z-index: 3;
}

/* 固定列内部的单元格也补上背景，避免出现条纹/遮挡错觉 */
.el-table__fixed .el-table__body-wrapper td,
.el-table__fixed-right .el-table__body-wrapper td {
	background: #fff;
}
```

### 2. ElementUI `el-select` 同时使用 `filterable` + `remote` 时，iOS 无法唤起键盘

**现象**
- 在 iOS（Safari / WKWebView / 企微内置）里，`el-select` 开启 `filterable` 且走 `remote-method` 时，点击输入框无法弹出键盘，导致无法输入搜索。

**原因**
- iOS 对“键盘弹起”要求更严格：必须由用户的直接交互触发 `focus`，且中途不能被组件内部的 `preventDefault`、焦点切换、或下拉层逻辑打断；ElementUI 的交互链路在部分内核下会导致 `focus` 失败或立即失焦。

**解决方案**
- 业务允许的话：iOS 端降级为 `el-autocomplete` / 自定义 `input + dropdown`，避免 `el-select` 的复杂焦点控制。
- 尝试在下拉展开时手动 `focus` 到真实输入框（需要确保在用户点击触发的同步链路中执行；异步 `setTimeout` 往往无效）。
- 兜底策略：在 iOS 环境禁用 `remote` 或禁用 `filterable`，改成“点开后展示常用项 + 搜索页”。

### 3. 企业微信内置浏览器：文件下载使用 `<a>` + `blob` 方式存在兼容性问题

**现象**
- 前端通过 `axios/fetch` 拿到 `blob`，用 `URL.createObjectURL(blob)` + `<a download>` 触发下载：在企业微信内置浏览器里可能不下载、打开空白页、或下载文件名/类型异常。

**原因**
- 企微内置浏览器内核与策略对 `blob:` URL、`download` 属性支持不一致；部分场景会把下载当成“预览/跳转”，或直接拦截。

**解决方案**
- 优先改为后端直出可下载 URL：设置 `Content-Disposition: attachment; filename=...`，前端直接 `location.href = url` / `window.open(url)`。
- 如果必须鉴权：后端提供一次性临时下载链接（带签名/短有效期），前端跳转该链接完成下载。
- 对于 iOS/企微内置：准备“预览 + 引导在系统浏览器打开”的降级路径。

### 4. 企业微信登录二维码样式调整：`href` 可以用 base64 形式

**现象**
- 企微登录二维码（通常是 iframe/图片）样式受限，直接调整尺寸/边距/圆角等不生效或被覆盖。

**原因**
- 二维码内容由第三方登录页渲染，样式隔离/跨域限制导致无法直接修改内部 DOM；只能从外部“替换/重绘”或通过链接参数间接处理。

**解决方案**
- 按文章思路：把二维码 `href` 改造为 base64 形式再注入/替换，从而在外层更好地控制展示与样式。

### 5. 浏览器“拖放默认行为”：会把图片数据插入到「当前焦点输入框」，而不是「鼠标释放时 hover 的输入框」

**现象**
- 页面里多个输入框/编辑器：把图片从桌面拖进页面松手时，图片（或其 base64/文件数据）会被插入到当前有焦点的输入框，而不是鼠标悬停/释放的那个。

**原因**
- 浏览器默认 drop 行为是基于“当前活动元素（focus）”处理可编辑内容，而不是基于 hover 命中的元素；因此焦点未切换时会插错地方。

**解决方案**
- 在可接收拖放的容器/输入框上显式阻止默认行为，并在 `drop` 时用事件目标做定向处理。
- 如果需要插入到具体输入框：在 `dragenter/dragover` 时主动给目标输入框 `focus()`（注意不要触发页面滚动/光标跳动）。

**示例（阻止默认 drop 并定向处理）**
```js
const onDragOver = (e) => e.preventDefault();
const onDrop = (e) => {
	e.preventDefault();
	const target = e.target;
	if (target && typeof target.focus === 'function') target.focus();
	// 这里再按业务读取 e.dataTransfer.files / e.dataTransfer.getData(...)
};
```

### 6. axios `GET` 请求在请求体为空时会删掉 `Content-Type`，避免 `GET + 请求体`

**现象**
- 使用 axios 发 `GET`，并且写了 `data`（哪怕是 `{}` / 空）时，抓包发现 `Content-Type` 可能不见了，后端也可能收不到期望的 body。

**原因**
- `GET` 语义上不建议带请求体；axios 也更倾向于把 `Content-Type` 等与 body 相关的头放在有 body 的方法（POST/PUT/PATCH）里处理。

**解决方案**
- 把参数放到 `params`（query string），不要用 `GET + data`。
- 如果业务确实需要 body：改用 `POST`（或由后端改造接口）。
- 不要依赖 `GET` 的 `Content-Type` 表达“请求体格式”。

### 7. textarea 在部分设备上：高度超过 `min-rows` 后文字发虚/模糊

**现象**
- textarea 自动增高（或手动设置高度）超过某个阈值后，字体边缘变糊、发虚，滚动/再次聚焦后可能恢复或更明显。

**原因**
- 常见与渲染缩放/小数像素有关：容器/页面存在 `transform: scale(...)`、非整数行高/高度、或某些设备的字体栅格化策略导致长区域重绘时抗锯齿表现异常。

**解决方案**
- 将texarea设置为自动高度（不限制高度），将固定高度放到外层容器（内部元素超出显示滚动条），避免 textarea 本身过高。
- 排查并避免在 textarea 祖先节点上使用 `transform/zoom` 等缩放属性（尤其是全局适配方案）。
- 尽量使用整数 `font-size` + 整数 `line-height`，避免高度/行高出现小数。
- 如果必须自动撑高：到阈值后改为固定高度 + 内部滚动（`overflow: auto`），减少大面积重绘。
- 极端机型：降级为 `contenteditable` 或自定义编辑器组件。

### 8. 复制 API 在 iOS 不支持“异步触发复制”，无法在后端请求返回后直接复制

**现象**
- 点击按钮后先请求后端拿文案，接口返回后再调用 `navigator.clipboard.writeText(text)`：在 iOS 上经常失败（无权限/无反应）。

**原因**
- iOS 对剪贴板写入要求强用户手势（user gesture）：复制必须发生在点击等同步事件栈内；一旦经过 `await`/Promise 异步链路，通常就不再被视为“用户触发”。

**解决方案**
- 预取：在用户点击“复制”之前就把文案请求回来并缓存，点击时同步复制。
- 降级：用隐藏 `textarea` + `document.execCommand('copy')`（同样要求在点击同步链路执行）。
- 再降级：弹窗展示文案，提示用户长按全选复制。

**示例（预取 + 同步复制）**
```js
let cacheText = '';
async function prefetch() {
	cacheText = await fetch('/api/text').then((r) => r.text());
}
function onCopyClick() {
	// 需在点击同步链路内执行
	navigator.clipboard?.writeText(cacheText);
}
```
